Overflow clipping: the CDK teleport advantage

.clip-box below is position: relative; overflow: hidden — a common real-world card/dropdown container. That makes it the hand-rolled popover's containing block, but floatingStyles still computes coordinates as if the containing block were the document root — so the popover renders at the wrong spot entirely and gets clipped away. The CDK version is unaffected: its content is teleported via Portal into the overlay container under body, so it never depends on an ancestor's positioning context.

Auto-flip at the viewport edge (CDK only)

Each reference below sits flush against the left edge of the viewport with placement="left" — there's no room to open on the left. The hand-rolled version has no fallback, so it renders off-screen. The CDK version's toConnectedPositions() always appends the opposite side as a fallback position, so FlexibleConnectedPositionStrategy automatically flips it to the right.
